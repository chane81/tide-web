# 스펙: tide 대시보드

Status: ready-for-agent

## Problem Statement

tide 디자인 시스템(`@tide-design/components`·`@tide-design/icons`)은 Storybook에서 컴포넌트 하나씩만 확인해 왔다. 여러 컴포넌트를 한 화면에 조합한 실제 웹에서 어떻게 보이는지, 실무 화면을 만들 때 무엇이 부족한지는 아직 모른다. 디자인 시스템 메인테이너는 배포된 패키지만으로 실제 대시보드를 만들어 보고, 보이는 모습과 부족한 점을 확인하고 싶다.

## Solution

npm에 배포된 tide 패키지를 설치한 Next.js 앱으로 SaaS형 대시보드를 만든다. 공통 셸(사이드바, 페이지 헤더, light/dark 테마 전환)과 다섯 화면(개요, 매출, 카드, 고객, 설정)으로 구성하며, tide 컴포넌트 대부분이 실제 맥락에서 쓰이게 한다. 데이터는 목업이다. tide에 없어 직접 조립하거나 덮어쓴 부분은 `docs/tide-gaps.md`에 쌓아 tide 쪽 개선 후보로 넘긴다.

## User Stories

### 확인하는 사람 (디자인 시스템 메인테이너)

1. 메인테이너로서, tide를 npm 배포본으로 설치한 앱을 원한다. 실제 사용자와 같은 조건에서 확인하기 위해서다.
2. 메인테이너로서, 설치 안내(전역 CSS 두 줄)만으로 스타일이 적용되는지 보고 싶다. 설치 문서가 맞는지 확인하기 위해서다.
3. 메인테이너로서, tide 컴포넌트를 서버 컴포넌트에서 래퍼 없이 import해 쓰는 앱을 원한다. RSC 호환이 실제로 되는지 확인하기 위해서다.
4. 메인테이너로서, 한 화면에 Card·Table·Tabs·Badge·Avatar 등이 함께 놓인 모습을 보고 싶다. 조합했을 때 간격·위계·색이 어울리는지 판단하기 위해서다.
5. 메인테이너로서, 같은 화면을 light와 dark 테마로 번갈아 보고 싶다. dark 토큰이 실제 화면에서 충분한지 확인하기 위해서다.
6. 메인테이너로서, tide에 없어서 직접 만든 것의 목록을 원한다. 다음에 tide에 추가할 컴포넌트를 고르기 위해서다.
7. 메인테이너로서, tide 컴포넌트의 모양을 `className`으로 덮어쓴 곳의 목록을 원한다. 컴포넌트 API가 부족한 지점을 찾기 위해서다.
8. 메인테이너로서, 앱 코드가 hex 색을 쓰지 않는 것을 원한다. tide 토큰만으로 대시보드를 칠할 수 있는지 확인하기 위해서다.
9. 메인테이너로서, 차트 색도 tide 토큰에서 오는 것을 원한다. 테마를 바꾸면 차트도 따라 바뀌는지 확인하기 위해서다.
10. 메인테이너로서, 좁은 화면(태블릿·모바일 폭)에서도 화면이 무너지지 않는 것을 원한다. tide 컴포넌트의 반응형 동작을 확인하기 위해서다.
11. 메인테이너로서, 키보드만으로 사이드바·탭·테이블·메뉴·다이얼로그를 조작할 수 있는 것을 원한다. tide의 접근성이 조합 화면에서도 유지되는지 확인하기 위해서다.

### 공통 셸

12. 사용자로서, 왼쪽 사이드바에서 다섯 화면으로 이동하고 싶다.
13. 사용자로서, 지금 보고 있는 화면이 사이드바에서 강조되어 보이길 원한다.
14. 사용자로서, 사이드바 메뉴 옆에 숫자 배지(예: 새 고객 수)를 보고 싶다.
15. 사용자로서, 사이드바 위쪽 검색 입력과 단축키 표시(⌘K)를 보고 싶다.
16. 사용자로서, 사이드바 아래쪽에서 내 이름·이메일·아바타를 보고, 누르면 계정 메뉴(프로필, 설정, 로그아웃)가 열리길 원한다.
17. 사용자로서, 사이드바 아래쪽 공지 카드(새 기능 안내)를 닫을 수 있길 원한다.
18. 사용자로서, 좁은 화면에서는 사이드바가 숨고 메뉴 버튼으로 열 수 있길 원한다.
19. 사용자로서, 각 화면 위쪽에 제목·설명·Breadcrumb·주요 액션 버튼이 있는 페이지 헤더를 보고 싶다.
20. 사용자로서, light/dark 테마를 전환하고 싶다.
21. 사용자로서, 선택한 테마가 새로고침 뒤에도 유지되길 원한다.
22. 사용자로서, 처음 방문하면 운영체제 테마 설정을 따르길 원한다.
23. 사용자로서, 테마가 바뀔 때 화면이 깜빡이지 않길 원한다(첫 렌더부터 올바른 테마).

### 개요 (`/`)

24. 사용자로서, 기간(12개월·30일·7일·24시간)을 탭으로 골라 지표를 바꿔 보고 싶다.
25. 사용자로서, MRR 같은 핵심 지표를 큰 숫자와 증감률 배지로 보고 싶다.
26. 사용자로서, 핵심 지표의 추이를 라인 차트로 보고 싶다.
27. 사용자로서, 보조 지표(전체 회원, 유료 회원, 메일 열람률)를 증감률과 함께 보고 싶다.
28. 사용자로서, 증가는 성공 색, 감소는 위험 색으로 구분해 보고 싶다.
29. 사용자로서, "시작하기" 바로가기 카드(첫 고객 추가, 보고서 만들기)를 보고 싶다.
30. 사용자로서, 상위 회원 목록을 아바타·가입일·온라인 상태와 함께 보고 싶다.

### 매출 (`/sales`)

31. 사용자로서, 오늘 매출·주문 수·평균 주문 금액을 KPI 카드로 보고 싶다.
32. 사용자로서, KPI 카드의 더보기 메뉴에서 동작(자세히 보기, 내보내기)을 고르고 싶다.
33. 사용자로서, 매출 보고서를 기간 탭으로 바꿔 가며 라인 차트로 보고 싶다(이번 기간과 지난 기간 두 줄).
34. 사용자로서, 월별 주문 수를 막대 차트로 보고 싶다.
35. 사용자로서, 차트 위에 마우스를 올리면 값이 툴팁으로 보이길 원한다.
36. 사용자로서, 최근 구매 활동 피드(누가 무엇을 샀는지)를 보고 싶다.
37. 사용자로서, "보고서 내보내기" 버튼을 누르면 완료 알림(Toast)을 보고 싶다.

### 카드 (`/cards`)

38. 사용자로서, 내 카드들을 카드 모양 비주얼로 보고 싶다(브랜드, 끝 네 자리, 만료일).
39. 사용자로서, 카드를 골라 그 카드의 잔액·한도 사용률(Progress)을 보고 싶다.
40. 사용자로서, 카테고리별 지출을 막대 또는 진행 막대로 보고 싶다.
41. 사용자로서, 거래 내역을 테이블로 보고 싶다(가맹점, 날짜, 금액, 상태 배지).
42. 사용자로서, 거래 내역을 페이지 단위로 넘겨 보고 싶다.
43. 사용자로서, 거래 상태(완료·대기·취소)를 배지 색으로 구분해 보고 싶다.
44. 사용자로서, "카드 추가" 버튼으로 카드 추가 다이얼로그를 열고 싶다.

### 고객 (`/customers`)

45. 사용자로서, 고객 목록을 테이블로 보고 싶다(이름·아바타, 이메일, 상태, 가입일, 결제 금액).
46. 사용자로서, 이름·이메일로 고객을 검색하고 싶다.
47. 사용자로서, 상태(활성·휴면·이탈)로 고객을 거르고 싶다.
48. 사용자로서, 열 머리글을 눌러 정렬하고 싶다.
49. 사용자로서, 행을 체크박스로 여러 개 고르고, 전체 선택도 하고 싶다.
50. 사용자로서, 고른 고객 수와 일괄 동작(내보내기, 삭제)을 보고 싶다.
51. 사용자로서, 일괄 삭제 전에 확인 다이얼로그(AlertDialog)를 보고 싶다.
52. 사용자로서, 검색·필터 결과를 페이지 단위로 넘겨 보고 싶다.
53. 사용자로서, 검색·필터를 바꾸면 첫 페이지로 돌아가길 원한다.
54. 사용자로서, 결과가 없으면 빈 상태 안내를 보고 싶다.
55. 사용자로서, 행을 누르면 고객 상세 다이얼로그를 보고 싶다.

### 설정 (`/settings`)

56. 사용자로서, 설정을 탭(프로필, 알림, 보안)으로 나눠 보고 싶다.
57. 사용자로서, 프로필 탭에서 이름·이메일·소개(Textarea)·역할(Select)·시간대(Combobox)를 고치고 싶다.
58. 사용자로서, 필수 입력이 비었거나 이메일 형식이 틀리면 필드 아래 오류 문구를 보고 싶다.
59. 사용자로서, 알림 탭에서 알림 채널을 스위치로 켜고 끄고, 알림 종류를 체크박스 그룹으로 고르고 싶다.
60. 사용자로서, 보안 탭에서 2단계 인증 방식을 라디오로 고르고 싶다.
61. 사용자로서, 저장을 누르면 저장 완료 Toast를 보고 싶다.
62. 사용자로서, 계정 삭제는 확인 다이얼로그를 거쳐야 하길 원한다.

### 로딩·상태

63. 사용자로서, 데이터가 오기 전에는 Skeleton으로 자리를 보고 싶다.
64. 사용자로서, 없는 주소로 가면 안내 화면과 홈으로 가는 링크를 보고 싶다.

## Implementation Decisions

- **앱 형태**: Next.js App Router 단일 앱(ADR 0001). 패키지 매니저 pnpm, 외부 의존성 버전은 `pnpm-workspace.yaml` catalog로 관리한다. Node는 `.node-version`(26).
- **tide 설치**: `@tide-design/components`·`@tide-design/icons` npm 배포본(작성 시점 0.11.4). 전역 CSS는 설치 안내 그대로 `tailwindcss` + tide `styles.css` 두 줄. Tailwind CSS v4 + `@tailwindcss/postcss`.
- **도구**: oxlint(경고도 실패), oxfmt, TypeScript strict, Vitest + React Testing Library + jsdom. 스크립트 `dev`·`build`·`typecheck`·`test`·`lint`·`format`·`format:check`. 앱 `typecheck`는 `next typegen` 뒤 `tsc --noEmit`. 에디터 설정(`.vscode`)은 워크스페이스 TypeScript 사용, oxfmt 저장 시 포맷, 권장 확장(oxc, Tailwind CSS IntelliSense)을 둔다.
- **구조**: `.claude/rules/app-structure.md`를 따른다. 라우트 전용 코드는 라우트 `_src`, 여러 라우트가 쓰면 `src/`로 승격.
- **공통 셸 모듈**
  - Sidebar: tide에 없으므로 tide `Link`·`Badge`·`Avatar`·`Menu`·`Input`·`Card`로 조립한다. 메뉴 항목 목록은 앱 상수로 두고 props로 넘긴다. 현재 경로로 활성 항목을 고른다.
  - PageHeader: 제목·설명·Breadcrumb·액션 슬롯.
  - 테마: `<html data-theme="light|dark">`로 전환한다(tide 방식). 선택은 localStorage에 저장하고, 첫 방문은 `prefers-color-scheme`을 따른다. 첫 렌더 깜빡임을 막으려고 hydration 전에 `data-theme`을 정하는 짧은 인라인 스크립트를 둔다. 토글은 client 컴포넌트 하나.
  - 모바일 폭에서는 사이드바를 숨기고 메뉴 버튼으로 연다(오버레이).
- **데이터 계층**: 모든 데이터는 목업이며 `apis/` 함수(`getXxx`)로만 읽는다. 함수는 async이고 응답 타입은 `<resource>.types.ts`에 둔다. 목록 함수는 서버 쪽 검색·필터·정렬·페이지를 받지 않고 전체를 돌려주며, 목록 가공은 client의 `libs/` 순수 함수가 맡는다(목업 규모가 작기 때문).
  - 리소스: 개요 지표(기간별), 매출 KPI·시계열·활동, 카드·거래, 고객, 설정 프로필.
  - 목업은 결정적(고정 시드)이어야 한다. 서버·클라이언트 렌더 결과가 같아야 hydration 오류가 없다.
- **가공 함수(libs)**: 통화·퍼센트·날짜 포맷(`Intl`, ko-KR / USD), 증감률 계산과 방향(증가·감소·같음) 판정, 기간별 시계열 자르기·집계, 목록 검색·필터·정렬·페이지 나누기.
- **고객 테이블 상태**: 검색어·상태 필터·정렬(열, 방향)·페이지·선택 집합을 하나의 훅이 관리한다. 검색어·필터가 바뀌면 페이지를 1로 되돌린다. 전체 선택은 현재 결과 전체를 대상으로 한다. 상태는 URL에 싣지 않는다.
- **차트**: Recharts(ADR 0002). 라인(개요 MRR, 매출 보고서 2계열)과 막대(월별 주문, 카테고리별 지출). 색·격자·축 글자색은 tide CSS 변수(`var(--…)`)로 넘긴다. 차트 래퍼 파일만 `'use client'`. 공통 차트 래퍼(색 연결, 반응형 컨테이너, 툴팁 모양)는 두 라우트 이상이 쓰므로 앱 전역에 둔다.
- **서버/클라이언트 경계**: 페이지와 카드는 서버 컴포넌트로 두고 `apis/` 함수를 직접 await한다. 상호작용(탭 전환, 테이블, 폼, 테마, 메뉴, 다이얼로그, Toast)은 잎 client 컴포넌트에서 한다. 기간 탭은 기간별 데이터를 미리 모두 받아 client에서 바꾼다.
- **로딩·오류**: 라우트별 `loading`은 tide Skeleton으로 카드 모양을 흉내 낸다. `not-found` 화면을 둔다.
- **설정 폼**: 저장은 목업이다(지연 후 성공 Toast). 검증은 client에서 필수·이메일 형식만 한다. 오류는 tide Field의 오류 표시를 쓴다.
- **tide 부족한 점 기록**: 직접 조립한 UI, `className` 덮어쓰기, 우회 코드가 생길 때마다 `docs/tide-gaps.md`에 한 줄 추가한다. 이 문서가 이 프로젝트의 핵심 산출물이다.
- **문구**: UI 문구는 한글. 금액은 USD 표기.

## Testing Decisions

- **좋은 테스트**: 바깥 동작만 본다. 함수는 입력→출력, 컴포넌트는 사용자가 보는 것과 하는 것(role·label로 찾고, 클릭·입력하고, 보이는 결과 확인). 내부 상태·훅 반환값·클래스 이름을 단언하지 않는다.
- **seam ①: `apis/`·`libs/` 함수 — Vitest 단위 테스트**
  - 포맷 함수(통화·퍼센트·날짜), 증감률과 방향 판정, 기간별 시계열 자르기, 검색·필터·정렬·페이지 나누기.
  - `apis/` 함수는 응답 모양과 결정성(두 번 불러도 같은 결과)을 확인한다.
- **seam ②: 상호작용 client 컴포넌트 — React Testing Library**
  - 고객 테이블: 검색·상태 필터·정렬·페이지 이동·필터 변경 시 첫 페이지 복귀·전체 선택·선택 수 표시·빈 상태·일괄 삭제 확인 다이얼로그.
  - 기간 탭: 탭을 바꾸면 지표 숫자가 바뀐다.
  - 테마 토글: 누르면 `<html>`의 `data-theme`이 바뀌고 저장된다.
  - 설정 폼: 필수·이메일 오류 문구, 저장 시 Toast.
  - 사이드바: 현재 경로 항목이 활성(`aria-current`)으로 표시된다.
- **테스트하지 않는 것**: 서버 컴포넌트 렌더, Recharts 그림, 레이아웃·색. 이것들은 `pnpm dev`로 브라우저에서 light/dark 둘 다 눈으로 확인한다.
- **기존 사례**: 이 저장소에는 아직 테스트가 없다. tide 저장소의 컴포넌트 테스트처럼 role·label 기준 조회를 따른다.
- 각 티켓은 `pnpm typecheck`·`pnpm lint`·`pnpm format:check`·`pnpm test`·`pnpm build`가 모두 통과해야 끝난다.

## Out of Scope

- 실제 백엔드·인증·로그인. 사용자와 데이터는 모두 목업이다.
- 데이터 변경의 영속화(저장·삭제는 Toast만 띄우고 목업을 바꾸지 않는다, 단 고객 일괄 삭제는 화면 상태에서만 지운다).
- 날짜 범위 선택기(DatePicker). tide에 없으므로 버튼 모양 자리만 두고 `docs/tide-gaps.md`에 적는다.
- ⌘K 검색 동작(명령 팔레트). 입력과 단축키 표시만 둔다.
- 국제화(i18n), 브랜드 색 추가(`tide-color` CLI).
- e2e·시각 회귀 테스트, 배포(CI/CD).
- tide 저장소 수정. 부족한 점은 기록만 한다.

## Further Notes

- 참고 레이아웃: SaaS 대시보드의 일반적인 구성(사이드바 + 헤더 + KPI 카드 + 차트 + 활동 목록 + 테이블)을 따른다. 특정 템플릿의 그림·문구·브랜드를 복제하지 않는다.
- tide 버전이 올라가면 업데이트 후 화면을 다시 확인하고, `docs/tide-gaps.md`에서 해결된 항목을 표시한다.
